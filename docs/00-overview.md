# 00. 개요와 범위 (hyper)

> 상태: 역할·범위·레퍼런스는 **확정**, 세부 모듈 경계는 **제안** · 기준일: 2026-11-17

`hyper`는 하이퍼리쉬 프레임워크 패밀리(`hyper`, `ring`, `lace`, `hera`)의 중심축이자, 모든 레이어가 수직 통합을 위해 기준(`ref`)으로 삼는 **코어 프레임워크 및 개발 환경 총괄** 레포입니다. 공통 추상 계약은 [`hyperish/docs`](https://github.com/hyperish/docs)를 따릅니다.

## 1. 확정된 역할과 도메인 범위

1. **개발 환경 및 생산성 총괄 (Toolchain & CLI)**
   - 프로젝트 스캐폴딩(`hyper init`), 실시간 핫리로드·미리보기(`hyper preview`), 정적 분석·포맷·진단(`hyper lint`), 단위·통합·매크로 진단 테스트(`hyper test`) 등 개발 전 주기를 단일 CLI와 워크플로로 통합 관리합니다.
2. **범용 코어 모듈 (`core` ref)**
   - **상태성(State & Reactivity)**: UI(`lace`, `hera`)와 백엔드/도메인(`ring`)이 공통으로 참조할 수 있는 신호(signal)·상태 그래프·수명 모델.
   - **직렬화(Serialization) & 파서(Parser)**: 고성능 내부 표현 직렬화/역직렬화 및 선언적 구문·에셋·스키마 파서.
   - **범용 연산 및 개발 프리미티브**: 비동기 실행·취소 토큰·구조화 오류·진단 리포팅 등 모든 레이어에서 반복 사용되는 기반 모듈.
3. **API 규격 인터페이스 통합**
   - 하이퍼리쉬 제품군과 개발 툴들이 백엔드(`ring`)·웹(`lace`)·네이티브(`hera`) 경계를 넘나들 때 사용하는 **스키마·RPC/API 규격 인터페이스**를 단일 선언으로 통합합니다.

## 2. 레퍼런스와 구현 전략 (확정)

| 축 | 레퍼런스 / 전략 | 채용 이유 |
|---|---|---|
| **DX & 매크로** | **Dioxus (`rsx!` 및 선언적 매크로, CLI)** | 읽기 쉽고 직관적인 매크로 표현과 통합 개발 도구(`dx`) 수준의 단일 명령 DX 달성 |
| **코어 구현** | **고성능 검증 크레이트 포크 + `unit optimization`** | 처음부터 전부 재발명하지 않고, 검증된 고성능 코어를 내부 포크·최적화하여 수직 통합 |
| **계층 수직화** | **`hyper` 코어를 `ref`로 삼고 그 위에 호환 어댑터 배치** | `ring`, `lace`, `hera`가 제각각 모델을 정의하지 않고 `hyper` 코어를 단일 원천으로 공유 |

## 3. 책임 경계: 소유하는 것과 소유하지 않는 것

- **소유함**:
  - 타깃 중립 코어 모델(`hyper-core`), 상태성(`hyper-state`), 직렬화(`hyper-serde`), 파서(`hyper-parser`), API 규격 계약(`hyper-api`), proc macro DSL(`hyper-macros`), 통합 CLI(`hyper-cli`).
- **소유하지 않음**:
  - 백엔드 전용 인프라·DB·MSA·WS/WT 런타임(`ring` 소관)
  - 브라우저 DOM·SSR/Hydration·웹 스타일링 파이프라인(`lace` 소관)
  - 데스크톱/모바일 GPU·CPU 렌더러 및 OS 네이티브 윈도잉(`hera` 소관)
- **의존 방향**:
  - `ring`, `lace`, `hera` → `hyper` (단방향). `hyper` 코어 크레이트는 특정 타깃(DOM, OS 윈도우, 특정 DB 드라이버)에 직접 의존하지 않으며, CLI(`apps/hyper-cli`)만 워크플로 오케스트레이션을 위해 각 타깃 러너를 호출합니다.
